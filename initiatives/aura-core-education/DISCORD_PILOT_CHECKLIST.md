# Discord Pilot Checklist

## Before inviting learners

- [ ] Confirm program owner and safety administrator.
- [ ] Define participant age range and jurisdiction.
- [ ] Obtain legal/privacy review appropriate to the pilot.
- [ ] Configure parent or guardian consent where required.
- [ ] Disable unnecessary direct messages and external invitations.
- [ ] Separate learner, adult, bot, and administrator roles.
- [ ] Restrict bot permissions to the minimum required channels and actions.
- [ ] Store secrets outside Discord and outside repository content.
- [ ] Create moderation, reporting, retention, and deletion procedures.
- [ ] Test every bot command with adult accounts first.

## Technical readiness

- [ ] Aura bot uses an allowlisted server and channel set.
- [ ] Code execution occurs only through an authenticated sandbox service.
- [ ] Submitted archives and text are size-limited and scanned.
- [ ] Network access from learner code is denied by default.
- [ ] CPU, memory, storage, and execution time are bounded.
- [ ] Project output is escaped before display.
- [ ] Administrative actions are audit logged.
- [ ] Public publishing requires a human approval step.
- [ ] Emergency shutdown and bot-token rotation are documented.

## Curriculum readiness

- [ ] Five starter missions are complete.
- [ ] Each mission has objectives, starter files, validation, and reflection.
- [ ] Aura's tutoring boundaries are tested.
- [ ] Educators can distinguish hints from generated solutions.
- [ ] Accessibility and controller navigation receive a basic review.

## Pilot exit criteria

- [ ] No unresolved high-severity safety incident.
- [ ] All submitted code remained inside the sandbox boundary.
- [ ] Participants could explain their projects.
- [ ] Educators found the review workflow usable.
- [ ] Retention and deletion requests were successfully tested.
- [ ] Findings and changes are recorded before expanding enrollment.
